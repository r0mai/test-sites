CSP + Tracker Blocking Test Suite

Purpose: These tests validate how DuckDuckGo browser's tracker blocking (via CDP Fetch interception) interacts with Content Security Policy and window.opener.

Test Cases

  • Test 1: CSP connect-src blocks tracker

    Page has connect-src 'self'. Attempts fetch to segment.com.

    Expected: CSP blocks before tracker blocker can intercept.

  • Test 2: CSP allows tracker, blocker blocks

    Page has connect-src 'self' https://segment.com. Attempts fetch to segment.com.

    Expected: Tracker blocker returns 403, no CSP violation.

  • Test 3: window.opener with blocked subresource

    Opens popup that loads blocked tracker. Checks if window.opener survives.

    Expected: window.opener should remain accessible.

  • Test 4: Surrogate script with strict CSP

    Page has strict script-src. Loads script that should be replaced with surrogate.

    Expected: Investigate if surrogate executes or CSP blocks it.

  • Test 5: Baseline - No CSP

    No CSP header. Attempts fetch to segment.com.

    Expected: Tracker blocker returns 403, clean baseline behavior.

How to Use

  1. Open each test in DuckDuckGo Windows browser
  2. Open DevTools (F12) → Network tab
  3. Run the test and observe:
    • Network tab: Status column, any CORS errors
    • Console tab: Error messages, CSP violations
    • Page results: Visual feedback on the page
  4. Compare behavior between WV2 and DDG WV (CEF)
