Test 6: Form POST with target="_blank" and window.opener

Scenario: A form submits via POST to a tracker URL with target="_blank". This opens a new window/tab that should have window.opener pointing back to this page.

Question: When tracker blocking intercepts a form POST navigation to a new window, does it affect the window.opener relationship? Does the new window even open?
Note: This tests a navigation-level POST (form submission), not a fetch/XHR POST. The browser may handle this differently than subresource requests.

Test A: Form POST to Tracker Domain (segment.io)

Submits form data to a known tracker. The tracker blocker should intercept this.

<form action="https://api.segment.io/v1/t" method="POST" target="_blank">

Test B: Form POST to Non-Tracker Domain (baseline)

Submits form data to a non-tracker URL for comparison. This should NOT be blocked.

<form action="test6-form-target.html" method="POST" target="_blank">

Test C: Form POST to Facebook Tracker

Submits to Facebook's tracking pixel endpoint.

<form action="https://www.facebook.com/tr" method="POST" target="_blank">
Submit a form above. The new window will report back its window.opener status.

How to Interpret Results

Outcome What it means
New window opens + has window.opener Normal behavior, opener relationship preserved
New window opens + NO window.opener Opener relationship broken (potential bug)
New window doesn't open Navigation was completely blocked
New window shows error page Blocked with error response (check window.opener)
