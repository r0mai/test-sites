Why they diverge: In DDG's CEF architecture, each tab has its own child HWND and WindowTreeHost. Unlike Chrome (one top-level HWND shared by all tabs), hidden tabs don't receive WM_SIZE/WM_DPICHANGED — so their host scale goes stale.

The OnDisplayMetricsChanged notification reaches all tabs, but Chromium's original code deferred the update when the scales didn't match, waiting for a WM_SIZE that never comes for hidden tabs.

The suppress_device_scale_factor_change_ Guard

Problem: RefreshScaleAndBounds updates the compositor scale, which triggers a Layer cascade: Compositor::SetScaleAndSize → Layer::OnDeviceScaleFactorChanged → cascades to all child layers → reaches RWHVA → SynchronizeVisualProperties.

But at this point, only the root window's DIP bounds were updated. The RWHVA's child window still has stale DIP bounds. The premature sync sends stale_DIP × new_scale = wrong size.

Solution: A base::AutoReset<bool> suppress_device_scale_factor_change_ flag suppresses OnDeviceScaleFactorChanged during RefreshScaleAndBounds. The correct sync happens right after, from ProcessDisplayMetricsChanged, when bounds have propagated.
